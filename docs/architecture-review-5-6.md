# 架构审查第 5、6 项修复记录

日期：2026-09-12。

## 草稿版本与恢复

剧情、人物、设定、碎片和关系编辑器统一使用带版本的草稿会话。

- 浏览器草稿格式升级为 v2，记录正文/表单、原始实体版本、开始编辑时的表单内容及保存时间。项目和工作区隔离方式保持不变。
- 恢复时保留真实的编辑版本。若数据库版本不同，或旧版草稿没有版本，显示版本冲突并阻止提交。再次关闭、打开也不会把旧草稿自动视为最新版本。
- 对比区显示开始编辑时的内容、最新已保存内容和当前草稿；旧格式缺失的原始内容明确标为未知。用户可在原编辑器中整理文本，对比确认后再保存。
- 确认只更新编辑基线，不直接写数据库。保存仍显式携带实体版本；对比期间另一个窗口再次写入时，后端继续拒绝冲突覆盖。
- 保存成功后推进本会话版本；后台详情刷新不替换活动草稿，迟到的旧详情不降低已保存版本。碎片编辑器连续创建章节时单独初始化新草稿会话。
- 浏览器写入失败会显示警告，底部只根据实际暂存结果显示成功或失败。断线通知不再无条件声称草稿已保存。

## 本地服务与静态入口

- 构建的 HTML 显式声明静态只读模式；本地服务返回 HTML 时声明本地模式，Vite 开发入口也声明本地模式。模式不再依赖 API 是否请求成功。
- 静态入口直接加载 `project.snapshot.json`，不探测本地服务，不呈现写入控件。
- 本地入口只读取 SQLite API。本地能力接口异常时显示服务连接问题，每两秒尝试恢复，并提供手动重试；不会读取旧静态快照。
- 已打开页面的同步失败时保留页面和输入，显示重连提示。恢复后原位同步；编辑草稿保留真实版本，仍需用户主动保存。
- 本地能力请求和快照请求有超时，避免连接无响应时永久等待。
- 本地 HTML 不缓存；需要让实际本地服务加载新后端代码，才能与本次前端模式标记配套使用。
