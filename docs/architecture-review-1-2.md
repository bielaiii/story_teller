# 架构审查第 1、2 项修复记录

日期：2026-09-11。

本次在工作区已有的第 3 项保存性能修复上继续修改，没有回退已有后台导出实现，也没有操作真实小说内容库。

## 1. 多窗口同步

- 增量仅在 `fromRevision` 等于本地版本时应用；已处理或迟到的响应不再覆盖当前缓存。
- 保存响应跨过中间版本时重新读取完整快照。快照回包也受版本单调性保护，避免较早发出的请求覆盖较新的保存结果。
- 本地模式在浏览器窗口聚焦、标签页重新可见和网络恢复时同步快照。失败时保留已有页面和输入；静态模式不启用此同步。
- 剧情、碎片阅读正文按实体版本更新，读取期间保留当前正文；阅读缓存与编辑器基线分开，避免正文同步重置草稿。
- 正在打开的编辑器使用详情版本作为保存基线，成功保存后推进本编辑器的基线。服务端即使收到最新项目版本，也会验证传入的实体版本，拒绝旧内容覆盖其他窗口的新修改。
- 后端增量的版本、变更集合、实体内容及结构数据在同一 SQLite 读事务中生成，避免返回标记为旧版本的新内容。

本项没有实现第 5 项的跨重载草稿版本存储和对比恢复；这里只补充了窗口同步必须具备的活动编辑基线保护。

## 2. 导出一致性

已有第 3 项修复使用共享读事务生成 Markdown、静态快照和恢复数据，并在进程内串行发布。本次进一步补齐：

- 所有普通读取上下文显式开启 SQLite 读事务，使多次查询具有一致视图。
- 导出开始读取前取得项目目录下 `.story-export.lock` 的排他锁，直至文件发布和状态记录完成后释放。后台服务、显式导出和 CLI 即使处于不同进程，也按相同顺序读取和发布。
- 导出锁独立于 SQLite 写锁；导出期间仍允许正文保存，后续任务再导出新版本。
- 导出版本保持单调；迟到成功或失败不覆盖较新完成状态，也不抹去较新任务的失败信息。
- 发布途中出现文件错误时恢复上一套文件，记录失败；重试从数据库重新生成。
- 锁文件保留固定 inode，并加入 Git 忽略规则；进程退出由操作系统释放锁。

边界：这里保证并发导出任务不会交错替换最终文件，且每次生成的数据来自同一版本。多文件替换并非外部文件读取者可见的单次原子目录切换；外部程序若恰好在发布途中读取整套文件，仍需等发布完成后重读。突然断电或强制结束进程的逐步故障注入不在本次验收范围内；正常异常回滚和后续重试已有覆盖。Windows 锁分支已实现，但本次跨进程实测在 macOS。
