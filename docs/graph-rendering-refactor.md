# Story Teller 图谱重构方案

状态：8.x 组织圆环与沿环文字已实施，完整图谱迁移仍在进行  
最后更新：2026-08-08  
适用范围：人物关系图谱、组织展示、关系与人物印象的可视化

## 1. 重构结论

这次重构的目标不是用更高级的技术绘制同样复杂的图，而是减少图谱需要持续执行的工作，并从结构上消除节点与连线不同步的问题。

核心变化只有四项：

1. 图谱空闲时停止动画循环；
2. 节点、连线和标签由同一个图谱主体渲染器绘制；
3. 组织成员使用附着在人物头像外侧的命名圆环表达，不使用大型组织背景框，也不自动展开成成员之间的大量连线；
4. 人物印象可以独立保存，不因为存在印象就自动生成常驻图谱连线。

第一阶段使用 Canvas 2D 即可。人物、圆环、关系和文字由一个语义场景 Canvas 完整绘制；持续动态只使用一个不参与交互的透明装饰 Canvas。WebGL 或 WebGPU 只在节点和关系规模确实超过 Canvas 2D 能力后评估，不能替代坐标统一、按需绘制和减少视觉元素。

当前进度：图谱主体已经切换到统一 Canvas 场景；人物、组织命名圆环、沿环文字、连线和标签在同一次底图绘制中完成。透明装饰 Canvas 只绘制少量动态光点，不持有人物或关系坐标，也不接收指针事件。拖拽、平移、缩放和选中仍通过同一套场景坐标处理。8.x 的组织投影已经删除临时组织背景框，改为附着在人物头像上的稳定命名圆环；关系与印象的数据模型和完整回归流程仍按后续迁移步骤推进。

## 2. 当前方案的问题

当前图谱主体由两种渲染方式组成：

```text
Canvas：关系曲线、粒子、箭头、关系标签
DOM：人物头像和人物节点
```

当前实现已经让两层读取同一份动画位置，修复了早期“节点移动后连线留在原处”的直接问题，但浏览器仍然需要分别处理 Canvas 绘制、DOM 样式更新和两层合成。

一次有效绘制包括：

- 清空 Canvas；
- 重新绘制全部关系曲线；
- 重新绘制粒子和方向箭头；
- 测量关系标签宽度；
- 绘制标签背景和文字；
- 更新每个人物 DOM 节点的位置；
- 合成 Canvas 与 DOM 图层。

即使用户没有操作，当前图谱仍会持续调度动画帧。降低绘制帧率只能减少部分绘制工作，并没有真正让图谱进入静止状态。

双渲染层还会持续带来这些风险：

- 缩放或平移时两层使用了不同的变换顺序；
- 拖拽结束时一层已经更新，另一层仍保留上一帧；
- 窗口尺寸变化后 Canvas 与 DOM 的坐标边界不同；
- 缓存失效时出现旧线、残影或短暂闪烁；
- 浏览器对 DOM 合成层和 Canvas 的调度差异造成手感不稳定。

## 3. 当前方案与目标方案对比

| 项目 | 当前方案 | 目标方案 |
|---|---|---|
| 人物节点 | DOM 按钮 | 图谱主体 Canvas |
| 关系连线 | Canvas | 与节点相同的 Canvas |
| 坐标来源 | 共享位置，但分别应用到 DOM 和 Canvas | 单一场景坐标直接绘制 |
| 空闲状态 | 持续调度动画帧 | 完全停止绘制 |
| 拖拽 | 更新 DOM，再重画 Canvas | 更新一个节点坐标，再重画同一场景 |
| 标签 | 动画过程中反复测量和绘制 | 数据或坐标变化时更新，可缓存 |
| 组织 | 大型背景框或成员之间的大量关系 | 使用头像外侧的命名圆环表达组织与身份 |
| 人物印象 | 容易与图谱关系绑定 | 独立保存，按需显示 |
| React 职责 | 同时承担页面和部分图谱节点 | 只负责页面、面板和数据提交 |
| WebGPU | 容易被当作性能补丁 | 仅作为未来渲染后端选项 |

## 4. 目标数据边界

图谱不能继续把所有有关联的数据都当成一条人物连线。领域数据至少区分以下对象：

```text
characters
organizations
organization_memberships
relationships
character_impressions
```

它们的职责分别是：

- `characters`：人物实体；
- `organizations`：家庭、黑帮、公司等组织实体；
- `organization_memberships`：人物在组织中的身份、职位和状态；
- `relationships`：确实存在持续或结构性联系的人物关系；
- `character_impressions`：某个人物对另一个人物的看法，可以脱离人物关系独立存在。

人物印象不自动产生图谱连线。它可以在人物详情中查看，也可以在用户聚焦相关人物时临时显示。

组织成员关系同样不自动转化为成员之间的两两人物关系。例如六人家庭默认在六名人物头像外显示同组织圆环，而不是生成一个大型背景框或十五条家庭内部连线。

## 5. 图谱投影层

SQLite 中的领域数据不直接交给渲染器，而是先转换成专用于显示的 `GraphScene`：

```text
SQLite 领域数据
       ↓
Graph Projector
       ↓
GraphScene
  ├── nodes
  ├── edges
  ├── memberships
  ├── labels
  └── visibility
       ↓
布局引擎
       ↓
统一渲染器
```

投影层负责决定：

- 哪些人物当前可见；
- 哪些关系作为常驻关系显示；
- 哪些弱关系只在聚焦人物后显示；
- 一条关系使用单线还是双线；
- 标签显示关系名称还是双方印象；
- 每个人物需要显示哪些组织圆环，以及圆环上的组织名称和身份；
- 当前缩放级别需要隐藏哪些标签和细节。

渲染器只负责忠实绘制 `GraphScene`，不在绘制循环里判断复杂的业务语义。

## 6. 单一坐标与单一主体渲染器

所有图谱对象使用同一套世界坐标：

```ts
interface GraphNode {
  id: string;
  x: number;
  y: number;
}

interface GraphViewport {
  x: number;
  y: number;
  scale: number;
}
```

交互统一经过坐标转换：

```text
鼠标屏幕坐标
    ↓ screenToWorld
图谱世界坐标
    ↓ 修改节点
场景失效
    ↓
在同一个 Canvas 中重新绘制节点和连线
```

Canvas 内部按以下顺序绘制：

```text
关系连线
  ↓
关系标签
  ↓
人物节点
  ↓
组织圆环与沿环文字
  ↓
选中与拖拽反馈
```

节点和连线在同一次底图绘制中读取同一份坐标，因此不再需要同步 DOM transform 与 Canvas 路径。装饰 Canvas 每帧也读取同一个场景和视口，但只画可丢弃的光点与高亮；即使它延迟一帧，也不会造成节点与关系线分离。

人物详情、关系编辑器、工具栏和键盘辅助仍然可以使用 DOM，但它们不得成为图谱节点位置或连线状态的第二个来源。

## 7. 绘制调度

图谱默认保持低频动态，但人物节点位置、关系路径和文字布局保持稳定，不运行持续的物理模拟。

绘制分为两档：

- 静置时底图保持不变，透明装饰 Canvas 以约 12 FPS 只绘制最多 8 条关系的慢速光点；
- 用户拖拽、平移、缩放、聚焦或移动指针时，短暂提升到约 30 FPS，并允许最多 18 条关系显示光点；
- 交互增强持续约 0.9–1.4 秒，随后自动回落到静置档；
- 浏览器标签页隐藏或系统开启“减少动态效果”时停止动态绘制。

以下情况使用交互档：

- 用户正在拖拽节点；
- 用户正在平移或缩放画布；
- 图谱正在执行短暂的聚焦过渡；
- 指针进入、移动或悬停人物时，短暂显示关系流动光点和人物呼吸光环。

静置状态应满足：

```text
语义场景 Canvas 重绘：0
装饰 Canvas 绘制：约 12 FPS
DOM 节点位置更新：0
节点物理模拟：0
布局重新计算：0
```

关系路径、标签尺寸和头像资源可以缓存。数据、坐标、主题或缩放级别改变时，才使相应缓存失效。

## 8. 视觉复杂度控制

图谱默认只显示：

- 人物节点；
- 人物所属组织的命名圆环；
- 核心人物关系；
- 必要的关系名称。

选中人物后可以增加显示：

- 与该人物有关的聚焦关系；
- 双方对对方的印象；
- 方向箭头；
- 完整关系标签。

缩放较小时应隐藏印象文字并降低无关关系透明度。组织圆环上的组织名和身份属于圆环的基本语义，不能只保留无法解释名称的无文字色环。图谱不能通过绘制更多元素来代替信息层级设计。

### 8.1 组织圆环

取消常驻的大型组织背景框。组织归属直接附着在人物头像外侧，视觉形态参考行星及其星环：

```text
头像本体
  ↓
第一条组织圆环
  ↓
第二条外侧组织圆环
  ↓
第三条外侧组织圆环
```

组织圆环必须同时满足：

- 一条圆环只表达一个组织；
- 人物加入多个组织时，从头像向外增加多条同心圆环，每条圆环使用递增半径区分层级；
- 同一组织在所有人物上使用稳定一致的颜色；
- 不同组织默认使用不同颜色；若组织配置颜色重复，图谱按稳定 ID 从共享色板中顺延选择未占用颜色；
- 圆环随人物节点一起移动，不维护独立的成员边界或组织包围框；
- 人物关系线仍连接人物节点，不连接组织圆环，避免组织归属与人物关系混为一谈；
- 默认最多直接绘制三条组织圆环，更多组织以明确的“另外 N 个组织”入口处理，避免头像周围堆叠过密。

### 8.2 沿圆环文字

圆环自身只能表达“存在组织归属”，不能解释组织名称，因此每条圆环必须直接携带组织名称和人物身份。

文字格式为：

```text
组织名称 · 身份
```

例如：

```text
卡斯特罗家族 · 家主
维斯珀黑帮 · 首领
```

排版要求：

- 文字沿对应圆形圆环的弧线排布，成为圆环本身的一部分；
- 上半圈文字保持从左到右阅读，禁止出现倒置文字；
- 字符始终朝向圆环外侧，并保持足够的字距和头像间距；
- 组织名称和身份必须直接使用文字，不使用菱形、圆点、星形等抽象符号替代；
- 不使用实线、虚线或透明度为成员状态增加额外语义；
- 本阶段只表达“属于哪个组织”和“在组织中的身份”，不在圆环上编码活跃、退出、失联等状态；
- 名称过长时允许按弧长截断并显示省略号，但选中人物后必须提供完整的组织名称和身份；
- 文字颜色、圆环颜色和人物头像之间必须有足够对比度，不能依赖颜色本身解释组织名称。

### 8.3 多组织排布

多条圆环使用递增半径的同心圆。第一条紧贴头像，后续圆环向外扩展形成行星星环层次；同一人物的不同圆环文字使用不同的上方弧段，避免文字互相覆盖。

同一人物的不同圆环文字应分布在不同弧段，避免互相覆盖；关系标签和关系线也需要在布局阶段避让圆环文字。圆环数量变化时只重算该人物的装饰边界，不触发整个图谱重新布局。

## 9. 布局规则

布局引擎只在以下情况重新计算：

- 第一次打开图谱；
- 新增或删除图谱节点；
- 组织成员发生变化；
- 用户点击“重新布局”；
- 图谱容器尺寸发生显著变化。

用户手动拖动后的节点位置作为持久化覆盖保存，不应被自动布局不断拉回。相同数据应生成基本稳定的初始布局，避免每次打开图谱时人物位置发生大幅变化。

节点规模增大后，布局计算可以迁移到 Web Worker；这与渲染器是否采用 WebGPU 是两个独立决策。

## 10. 迁移步骤

为了降低重构风险，按以下顺序迁移：

1. 从当前 `GraphPage` 中提取场景模型、投影规则和坐标转换；
2. 保留旧界面，建立新的单 Canvas 渲染器用于对照；
3. 接入节点、组织命名圆环、沿环文字、单线、双线和关系标签；
4. 接入命中测试、节点拖拽、画布平移和缩放；
5. 验证数据保存、选中状态和关系编辑器；
6. 切换到新渲染器；
7. 删除旧 DOM 节点层、旧动画循环和重复坐标逻辑；
8. 完成稳定性验证后，再决定是否需要 WebGL/WebGPU。

迁移期间不能让新旧渲染器分别修改人物坐标。对照模式只能读取同一份不可变场景快照。

## 11. 验收标准

功能与同步：

- 连续拖拽节点时，任意一帧的关系线端点都与节点中心重合；
- 拖拽结束、取消拖拽、窗口缩放和平移后没有残影、闪烁或偏移；
- 单向关系稳定显示一条线和一个标签；
- 双向关系稳定显示两条方向相反的线和两个标签；
- 只有印象、没有图谱关系时，不生成常驻连线；
- 组织成员不会自动展开成成员之间的两两关系；
- 图谱中不再绘制大型组织背景框；
- 每条组织圆环都能直接读出组织名称和人物身份；
- 多组织人物的圆环、沿环文字和人物关系线不会互相覆盖；
- 拖拽人物时，所有组织圆环及沿环文字与人物节点在同一帧移动；
- 组织圆环不使用抽象形状、实线/虚线或透明度编码额外成员状态；
- 隐藏关系、聚焦关系和选中状态只影响显示，不修改底层关系数据。

性能与调度：

- 静置动态限制为透明装饰 Canvas 上约 12 FPS、最多 8 条关系光点，语义场景底图不重绘；
- 交互动态限制为约 30 FPS，并在操作停止后自动回落到静置档；
- 拖拽和平移时保持稳定反馈，不出现明显输入延迟；
- 标签测量、头像解码和关系路径不会在无变化时重复执行；
- 图谱离开页面或浏览器标签页隐藏后停止所有绘制任务；
- 不支持 WebGPU 的浏览器仍然具备完整的图谱交互能力。

## 12. 不在本次重构中解决的问题

- 不通过重构自动判断人物之间是否应该存在剧情关系；
- 不把所有人物印象都转换为图谱边；
- 不为了展示效果开启持续的节点漂移、弹簧或物理模拟；
- 不在第一阶段引入复杂的 WebGPU 渲染管线；
- 不同时重写关系编辑器、人物编辑器和其他业务页面。

本次重构只建立一个稳定、按需绘制、语义清晰的图谱基础。后续视觉效果必须建立在该基础之上，并且不能重新引入双坐标源或持续空转的渲染循环。
